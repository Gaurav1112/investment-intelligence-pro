## Data and integrations

| Item | Status | Detail |
|---|---|---|
| AMFI NAVAll (latest NAV) | VERIFIED (live, 2026-10-15) | 14,376 rows parsed; 251 rejected with reasons (241 zero-NAV segregated portfolios, 10 bad ISINs). The first live run exposed two defects, both fixed: AMC lines missing in 4 sections, and a unit-string mismatch that marked every row rejected. |
| AMFI NAV history backfill | VERIFIED (live, 1 year, HDFC Liquid Direct Growth) | AMFI's fund-house ids are unpublished and are discovered by probing (1 request per id). Earliest available date and maximum range per request: NOT VERIFIED (≤ 90-day windows used). |
| Exit loads | REQUIRES CONFIGURATION | No public source. Each non-liquid fund needs a user-entered load with a citation; until then it is excluded (`EXIT_LOAD_UNKNOWN`). SEBI-defined loads (liquid graded, overnight none) are built in. |
| T-bill entered from an auction cut-off | Limitation | The cut-off yield is the primary-auction price on that date. You can only get it through a future non-competitive bid (RBI Retail Direct). A secondary-market purchase price will differ. Settlement is approximated as the next calendar day. Face value is bought in whole ₹10,000 lots (minimum ₹10,000, multiples of ₹10,000 — RBI/2021-2022/124 of 12-Nov-2021, VERIFIED-PRIMARY for that notification; no later amendment was found on 2026-10-15). The cash left over is held at 0 % and flagged `UNINVESTED_REMAINDER_AT_ZERO`; amounts below one lot's cost are `BELOW_MINIMUM_TICKET`. |
| Same NAV date from two AMFI sources | Handled | NAVAll and the history report overlap on recent dates. Equal values are merged. Unequal values exclude the scheme with `SOURCE_CONFLICT` (found in the live run, 2026-10-15). |
| T-bill yields, FD rates | REQUIRES CONFIGURATION (manual entry with citation) | RBI blocks scripted access (HTTP 418) and prohibits caching. Banks publish no API. |
| G-secs, SDLs, corporate bonds | REQUIRES CONFIGURATION (manual entry with citation); IMPLEMENTED, NOT VERIFIED against live quotes | Entered on Fixed income → "G-secs & bonds" (ISIN check digit validated; clean price per ₹100 **or** YTM, with its date and page URL). Nothing is fetched: NSE/BSE/CCIL/FBIL terms restrict automated use. Discovery, compare, scenario and simulate evaluate them with the QuantLib-checked engine. **Held to maturity** (maturity ≤ withdrawal): contractual coupons + redemption; coupons are kept as cash at 0 % until withdrawal (flagged); a callable bond takes the worst of its maturity and call paths. **Early exit** (maturity > withdrawal): a band of stress scenarios at the entry yield +100 / 0 / −100 bp plus the exit spread (25 bp G-sec/SDL, 100 bp corporate; NOT VERIFIED), tier T3, loss frequency unknown, so it is excluded for capital preservation. Unlisted corporates are never sold early. Quotes older than 7 days → `STALE_DATA`. Settlement is the next calendar day (no holiday calendar). Whole bonds only; the remainder stays as idle cash. A transaction spread left empty is computed at 0 and flagged `TRANSACTION_COST_UNKNOWN` (exit cost then counts as 100 %). Purchased accrued interest is not deducted from taxable interest (overstates tax); capital losses are taxed at 0 with no set-off (flagged). Odd first coupons are refused unless already paid before settlement; FRBs, STRIPS, inflation-indexed bonds and step-up coupons are out of scope. |
| SDL certainty tier | Design decision (conservative) | ADR-0005 puts only Government of India paper in T1 ("contractual sovereign"); risk-methodology §7.2 calls SDLs quasi-sovereign state credit, "shown separately". SDLs held to maturity are therefore **T2**, and the credit floor sees them as **AAA** (never SOVEREIGN), so a SOVEREIGN-only floor excludes them. Flag `SDL_STATE_GOVERNMENT_CREDIT_NOT_SOVEREIGN`. |
| Credit ratings | REQUIRES CONFIGURATION (manual entry with citation) | Rating agencies prohibit reproduction without consent, so ratings are never fetched. A corporate bond requires rating, agency, rating-action date and the rationale URL. A rating older than 12 months → `STALE_RATING`; none → `MISSING_RATING`; both exclude the bond. Below AAA, a bond held to maturity is T3 and fails preservation objectives (`UNINSURED_CREDIT_EXPOSURE`). Default and downgrade losses are not modelled; corporate loss frequency is unknown, never 0. |
| Scheme factsheet facts | REQUIRES CONFIGURATION (manual entry with citation) | Modified/Macaulay duration, portfolio YTM, average maturity, TER/BER, lowest rating held, share below AAA and share in sovereign/cash, per scheme and month (Instrument detail → "Enter factsheet facts"). History is kept; the latest is used; STALE beyond 45 days from the factsheet's as-of (month-end) date. Factsheets are never scraped. |
| CPI (MoSPI) | REQUIRES CONFIGURATION / IMPLEMENTED, NOT VERIFIED | Adapter `iip.data.mospi` reads `IIP_MOSPI_TOKEN` or `IIP_MOSPI_USER` + `IIP_MOSPI_PASSWORD` from the environment; unconfigured it reports REQUIRES_CONFIGURATION and makes no request. No authenticated call has been made: the login body field names, the general-index labels and base-2024 retrieval are unconfirmed, and any mismatch is refused (nothing stored). The realistic path is manual entry with a citation (Data health → Macro inputs). Base 2012 and base 2024 are separate series and never chained. |
| mfapi.in | Disabled by design | Unofficial mirror. Off by default; never an authority. |
| AMFI category taxonomy | Limitation, handled conservatively | The live NAVAll mixes about 100 labels: legacy ("Income" with 4,555 rows, "Growth", "Gilt"), SEBI-style, and the 2026 renamed ones. Ambiguous labels (index/ETF/FoF/hybrid/life-cycle/legacy) get tax class UNKNOWN, so those funds are excluded rather than guessed. ELSS lock-in is detected from both the category and the scheme name. FMP and interval schemes are refused as close-ended. |
| Survivorship | Limitation | NAVAll lists live schemes only. Merged or wound-up schemes are missing, which biases category statistics upwards. A banner is shown on fund results. |
| Holiday calendars | Limitation | No curated RBI/NSE holiday calendar is loaded. Business-day counts treat weekdays as business days and carry the note `CALENDAR_UNVERIFIED`. T-bill settlement is approximated as the next calendar day. |

## Analysis endpoints (Stage D)

| Item | Status | Detail |
|---|---|---|
| Inflation shock / real return | IMPLEMENTED, NOT VERIFIED (needs CPI input) | With a released CPI month (manual entry or MoSPI), `inflation_pct` returns Fisher real values and `/api/compare` rows carry `real_return`. π is the trailing 12-month CPI inflation (MoSPI's published YoY, or index(M)/index(M−12) **within one base**) compounded over the horizon — a labelled projection, not a forecast. Refused (`CPI_UNAVAILABLE`) without data, and (`CPI_STALE`) when the latest usable month is two or more months behind the latest release; one month behind is labelled STALE. Base 2012 and base 2024 are never chained. |
| Sharpe ratio | IMPLEMENTED, NOT VERIFIED (needs T-bill input) | Equity-type funds: Sharpe over the trailing 3-year window, excess over the 91-day T-bill cut-off series aligned to every return date (latest auction on or before it, ≤ 14 days old; risk-methodology §4.1). Refused as `RISK_FREE_SERIES_UNAVAILABLE` (no series), `RISK_FREE_SERIES_INSUFFICIENT` (any return date uncovered — nothing is filled in), `INSUFFICIENT_HISTORY` (< 3 years), and still `REFUSED_SMOOTHED_NAV` for debt, liquid and hybrid funds. Uses RBI auction cut-offs, not the licence-blocked FBIL curve. |
| Rate/spread shocks on debt funds | IMPLEMENTED, NOT VERIFIED (needs factsheet) | Debt-category funds with a factsheet modified duration: `rate_bp` via ΔV/V ≈ −D_mod·Δy, `spread_bp` with spread duration taken as the portfolio D_mod (overstates the loss: sovereign/cash has no spread; tightening and 100 % sovereign/cash funds are not applicable). Always labelled APPROXIMATE with the factsheet as-of date; STALE beyond 45 days. Hybrids are not applicable (factsheet duration covers only the debt portion). |
| Yield-carry range for debt funds (`/api/forecast`) | IMPLEMENTED, NOT VERIFIED (needs factsheet) | B4 (validation-methodology §2.4): (YTM − ER) × days/365 − D_mod × Δy over the −100…+100 bp grid plus +200 bp stress, as Explained values. Refused (`FUND_FACTS_UNAVAILABLE`) without YTM, duration and expense ratio, and (`STALE_DATA`) beyond 45 days. A BER entry is flagged: levies are not included, so carry is overstated. |
| FD early-exit scenario | IMPLEMENTED, NOT VERIFIED (needs card-rate table and penalty) | `exit_before_maturity_days` on an FD uses the bank's card rate for the tenure actually run (the bucket covering it, never a neighbour) minus the recorded penalty (calc §3.3, `fd_premature_withdrawal`). Not applicable without a table dated on or before the booking date and ≤ 30 days old, without a recorded penalty, or when no bucket covers the tenure. |
| Volatility for liquid/overnight/money-market funds | Refused by design | Their NAVs are smoothed. A weekly series is needed and has not been built. |
| Equity shock | Simplification, labelled | Applied to the fund's NAV with β = 1. Market beta is not estimated. |
| Scenario impacts | Before tax | Tax on the changed gain is not recomputed. |
| Forecast inputs | Note | NAVs are converted Decimal→float in the service layer before the forecasting engine, which is float-based by design. Outputs return to Decimal at the boundary. |
| DICGC aggregation | Conservative, with one gap | For a prospective FD, deposits already at that bank = the figure you entered with the FD **plus** open FD principal at cost at the same bank (same name and insured status) in all your actual portfolios (ECC F1). A figure that already includes those FDs is counted twice, and figures entered against several FDs at one bank are summed; both can only overstate. If neither a figure nor a recorded FD exists (e.g. an API call that omits it), cover cannot be established: the FD is flagged `EXISTING_DEPOSITS_NOT_RECORDED`, tier T3, UNRATED, never zero-loss. **Gap:** recorded FDs count at principal (accrued interest not added) and deposits held outside the app count only if you type them in. FDs entered before this change stored ₹0 when the figure was omitted and are read as ₹0; re-enter them to state the figure. |

## Findings from the red-team audit (docs/audit/final-red-team-report.md)

| Id | Status | Detail (and the test that pins it) |
|---|---|---|
| RT-17 | **Resolved 2026-10-15** | Post-coverage tax keeps the actual holding period: rates from the last legislated year (`rates_as_of`), classification from the real dates; equity held 400 days past coverage is LTCG at 12.5 % above the exemption (₹9,750, not ₹41,600). Tests: `tests/redteam/test_redteam_tax_coverage.py` — `test_rt17_equity_held_400_days_past_coverage_is_ltcg_at_12_5_percent`, `test_rt17_debt_mf_bought_after_2023_is_slab_regardless_of_holding`, `test_rt17_after_coverage_equals_actual_dates_under_unchanged_law` (never under- or overstates vs. that assumption, across the 1-Apr-2023, 23-Jul-2024 and grandfathering boundaries), `test_rt17_parity_within_coverage_nothing_changes`. |
| RT-18 | Flagged | Each option assumes the ₹1.25 lakh LTCG exemption is unused. Results that rely on it carry `LTCG_EXEMPTION_ASSUMED_UNUSED` — now reachable with the shipped table (`test_rt17_equity_mf_candidate_past_coverage_gets_ltcg_and_exemption_flag`). |
| RT-19 | **Resolved by user decision** (policy 1.1.0) | Preservation objectives require ≥ 20 independent windows. |
| RT-20 | **Resolved by user decision** (policy 1.1.0) | Growth objectives are refused for horizons under 12 months. |
| RT-21 | Fixed by final reviewer | Untracked schemes keep only their latest NAV; held, watched and backfilled schemes keep history. |
| RT-22 | **Resolved 2026-10-15** | (a) A fund is redeemed `settlement_days` before the withdrawal date, so the NAV window is H − settlement days and proceeds arrive in time (conservative); the redemption date also drives the exit-load test, the lock-in test and the tax transfer date. (b) T-bills: whole ₹10,000 lots, remainder at 0 %, `BELOW_MINIMUM_TICKET` below one lot (RBI/2021-2022/124). Tests: `tests/redteam/test_redteam_settlement_and_tickets.py` — `test_rt22a_nav_window_is_horizon_minus_settlement`, `test_rt22a_redemption_date_drives_holding_period_for_tax`, `test_rt22a_exit_load_judged_on_the_redemption_day`, `test_rt22b_tbill_below_minimum_ticket_is_ineligible`, `test_rt22b_exactly_one_lot_is_eligible`, `test_rt22b_tbill_face_in_whole_lots_and_leftover_cash_at_zero`. Formula ids `CAND_MF_EMPIRICAL@2`, `CAND_TBILL@2`; `candidates@1.1.0`. |
| RT-23 | **Fixed** (policy 1.2.0) | With a credit floor set, a debt-holding fund (debt, liquid, money-market, overnight, gilt, every hybrid) is checked by the lowest rating held from a factsheet ≤ 45 days old; with no usable factsheet it is excluded as `CREDIT_QUALITY_UNKNOWN`. Short-term ratings (A1+ …) are not mapped to the long-term scale, so they also count as unknown (conservative). Equity schemes are unaffected. ADR-0005 amendment. |
| RT-24 | **Resolved 2026-10-15** | Forecast (B1): a step longer than 7 calendar days is a gap; > 2 % of observations behind a gap → `DATA_GAPS_EXCEED_GATE` (suppressed, validation-methodology §8 with the risk-methodology §1 gate); otherwise every window spanning a gap is excluded (`GAP_WINDOWS_EXCLUDED`) and walk-forward origins whose outcome spans a gap are not scored. Feasibility keeps its own spec gate (§4.4.1: > 2 % suspect month-end points → reject); that rejection is now a REFUSED result instead of an error, and ≤ 2 % suspect points remain flagged `SUSPECT_GRID_POINTS` as the spec says. Tests: `tests/redteam/test_redteam_data_gaps.py` (8). |
| RT-26 | **Resolved 2026-10-15** (policy decided) | `canonical_json@2`: −0 → 0, aware datetimes → UTC, floats rejected anywhere, non-finite rejected. Exact Decimal digits are deliberately kept: published precision is provenance (`25.9504` ≠ `25.95040`), and computed Decimals are deterministic for identical inputs. Recorded as `canonical` in run versions (stored run hashes of earlier versions are not recomputed or compared anywhere). Tests: `tests/redteam/test_redteam_canonical.py`. |
| RT-27 | **Resolved 2026-10-15** | `include_fixtures` → 400 `FIXTURES_NOT_ALLOWED` in prod with no run stored; the MF history gate counts only usable rows (ok/manual/fixture, not superseded, one per date); FD ids are `fd:<institution_type>:<slug>:<tenure>d`. FDs entered under the old `fd:<slug>:<tenure>d` id keep working; re-entering one creates the new id (no user data existed at the change). Tests: `tests/redteam/test_redteam_rt27.py` (5). |
| RT-28 | **Resolved 2026-10-15** | XIRR with ≥ 2 sign changes searches each same-sign grid cell for an interior extremum; roots hidden there (crossing or double) give `NOT_DETERMINABLE` (`IRR_NOT_DETERMINABLE`), never "no root" or a single headline rate. Tests: `tests/redteam/test_redteam_xirr.py` (5). |

| Optional LLM explanations | Built, optional, off by default; IMPLEMENTED, NOT VERIFIED against a live model | One OpenAI-compatible adapter: a local loopback model, or an allowlisted free-tier cloud provider that receives a redacted packet. | CAS (CAMS/KFintech) statement import | **IMPLEMENTED, NOT VERIFIED** against a real CAMS/KFintech PDF | Detailed CAS (PDF + password) → preview → confirm with SHA-256 → apply (backup first, one transaction). Parsed in memory with casparser 1.4.1; tested only on a SYNTHETIC CAMS-style PDF generated at test time (fictional investor, RC4-128 encrypted) plus mapping unit tests. Real statement layouts are unverified until you import one. Known gaps: (1) schemes match only by the exact ISIN printed on the statement against locally stored instruments, and AMFI ingestion stores only Direct-plan Growth schemes (plus held/watched ones), so Regular-plan, IDCW and reinvestment-option ISINs are rejected as unmatched; (2) stamp duty, STT and TDS are ignored (the ledger has no fee transaction used by FIFO), so cost basis excludes stamp duty; (3) gifts, reversals and segregated-portfolio allotments are rejected and show up as reconciliation mismatches; (4) a statement that starts with an opening balance cannot reconcile and later sells may be refused as OVERSELL; (5) summary CAS and NSDL/CDSL depository CAS are refused (no transaction ledger); (6) CAS rows are stored with `source = csv_import` because the schema CHECK allows only `manual`/`csv_import` (widening it needs a table-rebuild migration); the import ledger records `kind = cas_pdf`; (7) the request body cap is the global 5 MiB (`Settings.max_body_bytes`), so the service's 10 MiB CAS cap is not reachable; (8) a PDF with an unsupported security *revision* of the Standard handler is reported by PDFium as a wrong password, not as unsupported encryption (an unknown security *handler* is reported correctly). |
